# gaku-ui：オーナーの美意識を、作るものに通す

オーナーはUIに厳しい。見て数秒で「ダサい」「好き」が決まる。「無難」「上品」「ちゃんとしてる」は褒め言葉ではない。
このスキルは、実際の判定（第2章）から引き出した原則（第3章以降）でできている。迷ったら第2章に戻って、似た判定を探す。

## 1. 一言で言うと

**今の時代の、研ぎ澄まされた道具の精度で、生きている映像を見せる。** 文字は大きさの差で語り、説明は画面の端に短く置く。

- 好きな系統：研ぎ澄まされた道具（Linear・Vercel・Apple・Raycast）、生成的な映像（WebGL・粒子・光・霧）、攻めたエディトリアル（巨大な文字、画面を割る配置）
- 嫌いなもの：古臭い・地味、動かない、定番の画面の着せ替え、物の真似（ダイヤル・計器・地図）、標準の部品そのまま、はっきり見える四角や線、AIの定番の飾り
- 用途は「作品」「自分で毎日使う道具」「他人に売るサービス」の全部。基準は同じ。変えるのは第7章の配分だけ

## 2. 判定の記録（根拠。増やしていく）

書き方：`何を見せたか → 判定「オーナーの言葉」→ 分かったこと`。新しい判定が出たら、ここに同じ形で足す。

### 好き・良い
- WebGL の色の場。点を置くとばねで揺れて境界が流れる（Field Lab）→「悪くはない」→ **映像が反応することが土台**
- 巨大な数字 `99` に小さな `%`（誌面）→「結構好き、大きさを変えることでアクセントが出てる」→ **大きさの差でアクセント**
- 文字の所だけすりガラス、端は消える。場は画面の端まで（誌面の直し）→「いいねええええ」→ **白い板で画面を分けない。映像は全面、文字の後ろだけぼかす。ぼかしの端は消す**
- 画面いっぱいの極太ワードマークを、映像に乗算で敷く →（採用）→ **小さいタイトル＋説明文の代わりになる**
- 絹のように流れる霧（KASUMI 1版）→「いいね」。粒子の霧（KASUMI 2版）→「いいねー好き」→ **柔らかい霧も良いが、粒の集まりはもっと良い。粒が時間で重くなる、など意味のある変化があると強い**
- スクロールで「吹きかけてからの時間」が進み、香りと霧が変わる → 採用 → **操作を、題材そのものの現象に結びつける**
- 和文 IBM Plex Sans JP ＋ 欧文 Geist ＋ 見出し Bricolage Grotesque / Syne → 通った

### ダサい・だめ
- 生成りの紙・明朝・字間を広げた題字（和音のサイト、地形図）→「上品すぎて地味」「古臭い・地味」→ **理由なく「昔」に寄せない**
- 計器盤・製図・スイス風の3案（同じパネル構成の色替え）→「AI感が出る」→ **着せ替えではAI感は消えない。構図と体験を変える**
- 地形図の見立て →「ネタが刺さらない」「動きが無い」→ **説明が要る見立ては負け。動かない画面は負け**
- 凡例の箱に標準のスライダー・ボタンを並べた →「だっせえ」→ **標準の部品を枠に入れて並べない**
- 円形のダイヤル（レンズ）→「元がダサいからどうしようもない」→ **物の真似の構図は、直しても救えない。案の段階で捨てる**
- 柔らかい場の中の、太い真っ黒の境界線 →「境界線がはっきりしてて違和感」→ **素材と合わない硬い線を入れない。線は映像に溶かす（細い光の継ぎ目など）**
- 削りすぎて、どの色が何か分からない →「シンプルにしすぎてどれがどれか分かりづらい」→ **分かりやすさは必要**
- 画面の真ん中の説明の札 →「どまんなかに置くとじゃま」→ **名札は画面の端に。そこから目盛りや点線で指す**
- 「まだ分からない（点が遠い）」の長い呼び名 →「ダサい。不明とか、英語とか」→ **呼び名は短い1語。英語1語でもよい**
- 左上の小さいタイトル＋1行の説明文 →「AIあるある過ぎてダサい」→ **使わない**
- 和文 Zen Kaku Gothic New →「日本語のフォントがダサい」→ **使わない**
- 誌面の白い板と場の境目 →「はっきり分かれてんじゃん」→ **硬い境目を作らない**
- 文の途中の改行（置い／た点）→「改行の位置がおかしい」→ **意味の区切りでだけ折る**
- タイトル「1行書けば、本番まで。」→「タイトルに『、』があるのは変」「英語か単語、文っぽくない文」→ **タイトルは英語か単語。句読点なし**
- 粒を四角で描いた・塗り重ねの残像 →「はっきり四角がわかんじゃん」→ **意図しない四角・切れ目・残像を残さない**
- 関所の縦線（すりガラスの下で太さが変わる）→「縦のラインが見えるのが気になる、急にズームしてる感じ」→ **全面の長い線を引かない。ぼかしの層の下に線や粒を置かない（上の層に描く）**
- 粒子が流れの溝に集まって線になった →（自分で発見）→ **粒子の流れは渦だけ（発散しない場）にする**

### 条件つき
- ひげ文字・黒と金の古い印刷物風 → 音楽のサイトだったから頼んだ → **題材が求めるなら古い様式も使う。題材と無関係に使わない**
- 画面の明暗 → 「内容で変えていい」→ **題材・中身で決める。内容が変わるとき、部屋ごと変える（KASUMI の朝／夕／夜）のは良い**

## 3. 原則（判定から）

1. **体験が先、見た目は後。** 最初の5秒に「生きている映像」と「触ると返ってくる反応」がある。これが無い案は出さない
2. **構図で勝負する。** 定番の画面（左にパネル、右に本体、下にバー）に色を塗っても負ける。全画面の映像に、文字と操作を浮かべる。画面を板で分けない
3. **題材の現象を操作にする。** スクロール＝時間、ドラッグ＝かき混ぜ、置く＝学習。「〇〇に見立てる」ではなく、題材そのものが動く
4. **大きさの差で語る。** 巨大な数字と小さな単位、巨大なワードマークと小さな名札。段は少なく、差は大きく
5. **言葉は短く。** 名札は1語（英語可）。タイトルは英語か単語、句読点なし。説明文で補わない。日本語の本文は意味の区切りでだけ折る
6. **端に置く。** 名札・操作・補足は画面の端。中央は映像のもの。端から目盛りや点線で対象を指す
7. **硬いものを混ぜない。** 柔らかい映像に、黒い太線・四角・切れ目・全面の縦線を入れない。線は細い光、端はグラデーションで消す、ぼかしの端も消す
8. **分かりやすさは削らない。** 何が何か、どこを触るかは画面の中で分かる。ただし説明は端に、短く
9. **古い様式は題材が求めるときだけ。** 紙・明朝・レトロは、理由なく使わない
10. **部品は自分で作る。** 標準のスライダー・ボタン・チェックボックスを枠に入れて並べない。キーボード操作とフォーカスは必ず残す

## 4. AIが作った感の正体（全部避ける）

生成りの背景＋セリフ＋テラコッタ／黒地に蛍光1色／新聞風の細い罫線と段組み／同じ角丸・同じ影のカードの並び／飾りのグラデーション／見出し上の字間を空けた大文字ラベル／「A · B · C」の中黒つなぎ／小さいデータに等幅フォント／ボタンの後ろの「→」／数字タイルの羅列／01・02・03 の番号（順番が無いのに）／見出しの1語だけ色替え／何でも中央揃え／全節に同じふわっと出るアニメーション／見出しの絵文字／Inter・Space Grotesk・Roboto・Noto Sans JP を「とりあえず」／左上の小さいタイトル＋説明文／パネルで区切った定番の画面

## 5. 通った素材

- 和文：**IBM Plex Sans JP**（400/500/700）。使わない：Zen Kaku Gothic New、明朝（題材が求めるときだけ）
- 欧文・数字：**Geist**（数字は `tabular-nums`、巨大な数字は 600 で字間 -0.06〜-0.07em）
- 見出し・ワードマーク：**Syne 800**、**Bricolage Grotesque 800**（`opsz` 96）。字間 -0.04〜-0.07em
- 色の組み方：地の色＋文字の色＋**強い色を1〜2色**。例：薄い灰白 `#F3F3F0` に インターナショナルオレンジ `#FF4F00` と 電気の青 `#1F4BFF`／夜 `#0D0F14` に 骨色 `#ECE8DF` と 信号の青 `#5B7CFF`。灰色は差し色に少し寄せる
- 明暗は題材で決める。中身が切り替わるとき、地の色ごと変えてよい（CSS 変数を `data-*` で切り替え、`transition .9s`）

## 6. 動きと映像の作り方（数値つき）

- 操作への反応は **100ms 以内**。動きは時間ではなく物理で：ばね `k 300〜500, c 25〜35`（画面の値）、色や位置の追従は `k 24〜140, c 9〜20`
- 状態が変わるときは、前の形から次の形へ**流れる途中**を見せる
- 何もしていなくても、1つだけ生きている動き（脈、漂い）。2つ以上は置かない
- **場（連続した色）**：WebGL のフラグメントで、fbm ノイズ＋ドメインワープ。柔らかくするなら周波数を下げ（`p*0.6`）、ワープは弱く（`0.8〜0.9`）、4オクターブ。描画は 0.5〜0.6 倍の解像度で描いて引き伸ばす
- **粒子**：WebGL の点スプライト。小さな粒 数千〜1万（スマホ 1/3）＋大きく薄い靄 数百。流れは**ノイズの curl**（発散しない）＋ごく小さな乱れ。暗い地は加算（`SRC_ALPHA, ONE`）、明るい地は通常の合成で、色は地より濃く。四角を描かない（丸い点、`smoothstep` の縁）
- **かき混ぜ**：ポインタ周りで回転か接線方向の押し出し。強さはポインタの速さで決め、減衰する
- **ぼかしの層**：`backdrop-filter: blur()` の板は、端を `mask-image` のグラデーションで消す。その板の下に線や粒を置かない。粒は板より上の層（別の canvas）に描く
- `prefers-reduced-motion: reduce`：動きを止めるか、短い切り替えだけ。60fps を守る

## 7. 用途ごとの配分（基準は同じ、比重だけ変える）

| 用途 | 映像・驚き | 分かりやすさ | 速さ・軽さ |
| --- | --- | --- | --- |
| 作品（ポートフォリオ） | 最大。見た人が「すげぇ」と言う所を1つ | 端の名札で足りる | 重くてもよいが 60fps |
| 自分で毎日使う道具 | 1か所に抑える。毎日見て疲れない | 最大。状態が一目で分かる | 最大。待たせない |
| 他人に売るサービス | 最初の画面だけ強く | 迷わせない。文言は短く具体的に | 速い。スマホ優先 |

どの用途でも、第3章の原則と第4章の禁止は変えない。

## 8. 手順

1. **体験の核を1文で書く**（動きと手触りで。「〇〇風」は不可）。核が無い案は作らない
2. **構図の違う3案**を出し、比べる（例：全画面の映像に操作が浮く／巨大な文字と映像を並べる誌面／1つの題材の現象に全部を乗せる）。物の真似の構図は候補に入れない。オーナーに見せられるときは3案を見せる
3. **設計表**（色4〜6、文字2役割、構図のラフ、動きの数値）をコードの先頭にトークンとして残す
4. **作る**。映像は WebGL か canvas。部品は自作。文言は短く。日本語の文は `、` と `。` で分けた `span` に
5. **スクショを PC とスマホで撮り、第9章を全部 Yes にする**。最後に飾りを1つ外す
6. **オーナーの判定を受けたら、言葉をそのまま第2章に足す。** 「ダサい」と言われたら、色やフォントの調整で済ませず、構図か体験を変える

## 9. 仕上がりのチェック

- [ ] 最初の5秒に、生きている映像と、触ると返る反応がある
- [ ] 定番の画面の着せ替えになっていない。板で画面を分けていない
- [ ] 操作が題材の現象に結びついている（説明が要る見立てではない）
- [ ] 巨大と小さいの差がある。小さいタイトル＋説明文が無い
- [ ] 名札は端にあり、1語で、タイトルは英語か単語で句読点なし
- [ ] 硬い線・四角・切れ目・残像・全面の縦線が無い。ぼかしの端は消えている
- [ ] 何が何かが画面の中で分かる
- [ ] 理由なく紙・明朝・レトロに寄っていない
- [ ] 標準の部品を枠に並べていない。キーボードで操作でき、フォーカスが見える
- [ ] スマホで同じ体験。横にはみ出さない。日本語が文の途中で折れていない
- [ ] 第4章のどれにも当てはまらない
- [ ] 飾りを1つ外した

## 10. レビューのとき

画面に触る変更は、第2章の判定・第4章・第9章で確かめる。当てはまる物を「どこが・なぜ・どう直すか」で具体的に指摘する。好みの問題で済ませない。色やフォントの差し替えで済む指摘と、構図や体験を変えるべき指摘を分けて書く。
