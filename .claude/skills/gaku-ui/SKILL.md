# gaku-ui：オーナーの美意識に届く画面を、手順どおりに作る

オーナーはUIに厳しい。見て数秒で「ダサい」「好き」が決まる。「無難」「上品」「ちゃんとしてる」は褒め言葉ではない。
このスキルは **(A) 判定の記録**（根拠）、**(B) 迷わない決めごと**、**(C) 手順**、**(D) 部品**（`references/recipes.md`、写して使う）でできている。
**自分の判断で決めてよい所は少ない。** 決めごとと手順に従い、部品はコードごと写す。自分の発想で足すのは「題材の現象をどう操作にするか」の1点だけ。

## 一言で

**今の時代の、研ぎ澄まされた道具の精度で、生きている映像を見せる。** 文字は大きさの差で語り、説明は画面の端に短く置く。操作は、題材そのものの現象に結びつける。

---

## A. 判定の記録（根拠。増やしていく）

書き方：`何を見せたか → 判定「オーナーの言葉」→ 分かったこと`。新しい判定が出たら、同じ形で足す。

### 好き・良い
- WebGL の色の場。点を置くとばねで揺れて境界が流れる（Field Lab）→「悪くはない」→ 映像が反応することが土台
- 巨大な数字 `99` に小さな `%` →「結構好き、大きさを変えることでアクセントが出てる」→ 大きさの差でアクセント
- 文字の所だけすりガラス、端は消える。映像は画面の端まで →「いいねええええ」→ 白い板で画面を分けない
- 画面いっぱいの極太ワードマークを映像に敷く →（採用）→ 小さいタイトル＋説明文の代わりになる
- 絹のように流れる霧 →「いいね」。粒子の霧 →「いいねー好き」→ 粒の集まりが一番強い。粒が時間で重くなる、など意味のある変化があるとさらに良い
- スクロールで「吹きかけてからの時間」が進み、香りと霧が変わる（KASUMI）→ 採用 → 操作を、題材そのものの現象に結びつける
- 和文 IBM Plex Sans JP ＋ 欧文 Geist ＋ 見出し Syne / Bricolage Grotesque → 通った

### ダサい・だめ
- 生成りの紙・明朝・字間を広げた題字 →「上品すぎて地味」「古臭い・地味」→ 理由なく「昔」に寄せない
- 計器盤・製図・スイス風の3案（同じパネル構成の色替え）→「AI感が出る」→ 着せ替えではAI感は消えない。構図と体験を変える
- 地形図の見立て →「ネタが刺さらない」「動きが無い」→ 説明が要る見立ては負け。動かない画面は負け
- 凡例の箱に標準のスライダー・ボタン →「だっせえ」→ 標準の部品を枠に入れて並べない
- 円形のダイヤル（レンズ）→「元がダサいからどうしようもない」→ 物の真似の構図は案の段階で捨てる
- 柔らかい場の中の太い真っ黒の境界線 →「境界線がはっきりしてて違和感」→ 線は映像に溶かす（細い光の継ぎ目）
- 削りすぎ →「シンプルにしすぎてどれがどれか分かりづらい」→ 分かりやすさは必要
- 画面の真ん中の説明の札 →「どまんなかに置くとじゃま」→ 名札は端。端から目盛りや点線で指す
- 長い呼び名「まだ分からない（点が遠い）」→「ダサい。不明とか、英語とか」→ 名札は1語。英語1語でもよい
- 左上の小さいタイトル＋1行の説明文 →「AIあるある過ぎてダサい」→ 使わない
- 和文 Zen Kaku Gothic New →「日本語のフォントがダサい」→ 使わない
- 白い板と映像の境目 →「はっきり分かれてんじゃん」→ 硬い境目を作らない
- 文の途中の改行 →「改行の位置がおかしい」→ 意味の区切りでだけ折る
- タイトル「1行書けば、本番まで。」→「『、』があるのは変」「英語か単語、文っぽくない文」→ タイトルは英語か単語。句読点なし
- 粒を四角で描いた・塗り重ねの残像 →「はっきり四角がわかんじゃん」→ 意図しない四角・切れ目・残像を残さない
- 全面の縦線（ぼかしの板の下で太さが変わる）→「縦のラインが気になる、急にズームしてる感じ」→ 全面の長い線を引かない。ぼかしの板の下に線や粒を置かない
- 粒子が流れの溝に集まって線になった →（自分で発見）→ 粒子の流れはノイズの curl（発散しない）にする

### 条件つき
- ひげ文字・黒と金の古い印刷物風 → 音楽のサイトだったから頼んだ → 題材が求めるなら古い様式も使う。無関係には使わない
- 画面の明暗 →「内容で変えていい」→ 題材で決める。内容が切り替わるとき、部屋ごと変えるのは良い

## B. 迷わない決めごと（ここで悩まない。そのまま使う）

### 文字
- 和文：**IBM Plex Sans JP**（400/500/700）。使わない：Zen Kaku Gothic New、Noto Sans JP、明朝（題材が求めるときだけ）
- 欧文・数字：**Geist**（400/500/600）。数字は `font-variant-numeric: tabular-nums`
- ワードマーク・巨大な語：**Syne 800** か **Bricolage Grotesque 800**。字間 `-0.05em`
- 大きさは4段だけ：巨大 `clamp(96px,18vw,230px)`（数字）／見出し `clamp(56px,7vw,104px)`／本文 `16px`／名札 `13px`。この間の大きさを作らない
- 巨大な数字の字間 `-0.07em`、行の高さ `.82`。単位は数字の `.14〜.18` 倍で `--mute` 色
- 日本語の本文は 11.5px 未満にしない。`word-break: auto-phrase` を body に。文は `、。` で分けた `span` に

### 色
- トークンは5つだけ：`--ground`（地）、`--ink`（文字）、`--mute`（文字の55%）、`--hair`（文字の12〜16%の線）、`--signal`（強い色、1〜2色）。これ以外の色を直接書かない
- 地は題材で決める。明るいなら `#F3F3F0` 系（真っ白にしない）、暗いなら `#0D0F14`〜`#1B1411` 系（真っ黒にしない。青か暖色に少し寄せる）
- 強い色の例：インターナショナルオレンジ `#FF4F00`、電気の青 `#1F4BFF`、信号の青 `#5B7CFF`。蛍光の緑・朱・紫は使わない
- 映像の色は、地の上で見える濃さにする（明るい地なら地より濃く、暗い地なら光らせる）

### 構図（この3つから選ぶ。ほかは作らない）
- **型1 全画面**：映像が全面。左上に見出し（英語1〜2語）、下に浮いた操作のバー（すりガラス、角丸16px、高さ46〜48px）。名札は右端
- **型2 誌面**：映像が全面。左 `min(46%,620px)` に文字の列（巨大な数字＋2行の文）。列の後ろだけすりガラス、右端は mask で消す。操作は列の下。名札は右端
- **型3 現象**：映像が全面で、ページのスクロールやドラッグが題材の現象（時間・温度・距離・量）を進める。左に巨大な数字（現象の値）、右端に段階の名札、左下に切り替え、右下に行動（買う・始める）
- 画面を板で左右に分けない。パネル・カードを並べない。物の真似（ダイヤル・計器・地図・紙）の構図を作らない

### 映像（1つ選ぶ。`references/recipes.md` の 7 か 8 を写す）
- **粒子の霧**（第一候補）：小さな粒 9,000（スマホ 3,200）＋薄い靄 360。流れは curl。暗い地は加算
- **色の場**：fbm＋弱いワープ、4オクターブ、0.5〜0.6倍の解像度
- 映像は必ず「題材の値」で変わる（時間で粒が重くなる、点を置くと境界が流れる）。飾りで動かさない
- 何もしなくても1つだけ生きている動き（粒の漂い、脈）。2つ以上は置かない

### 動き
- 操作への反応は 100ms 以内。全部ばね（`recipes.md` 6）。画面の値は `k 300〜500, c 25〜35`、色や位置の追従は `k 24〜140, c 9〜20`
- 切り替えは、前の形から次の形へ流れる途中を見せる。地の色の切り替えは CSS `transition .9s`
- `prefers-reduced-motion: reduce` では、動きを止めて即座に合わせる。60fps を守る（重いなら粒を減らす、解像度を下げる）

### 言葉
- タイトル・見出し：英語か単語。句読点なし（`KASUMI` `One Line to Prod` `Field Lab`）
- 名札：1語（`Top` `Boundary` `Unknown`）。数を添えるなら小さく（`Orange 46`）
- 本文：短く、具体的に。説明で見立てを補わない。「〇〇 ― 〇〇する」のサブタイトルを書かない
- 操作の文言：何が起きるかそのまま（「カートに入れる」→押したら「入れました」）

### 層の順番（下から）
地の色 → 映像の canvas → ぼかしの板（文字の後ろだけ、端は mask で消す）→ 粒や線の canvas（**ぼかしの上**）→ 文字・名札・操作

## C. 手順（順番どおりに。飛ばさない）

1. **題材の現象を1つ選ぶ。** 「この題材で、時間・量・距離・熱・濃さのどれが動くか」を書く。例：香水→吹きかけてからの時間、分類器→点を置いたときの境界、公開パイプライン→1行が関所を通る
2. **体験の核を1文で書く。** 「〇〇すると、映像が〇〇して、〇〇が変わる」の形。動きと手触りで書く。「〇〇風の見た目」は不可。核が書けない題材は、まず題材を見直す
3. **構図の型を選ぶ**（B の3型から1つ）。オーナーに見せられるときは、3型を並べて選んでもらう。1案だけ作って磨かない
4. **設計表を書く**（`recipes.md` 0 の `:root` を埋める）。色5つ、フォント3役割、型、映像の種類、題材の値がどう映像を変えるか
5. **骨組みを写す**（`recipes.md` 0）→ **映像を写す**（7 か 8）→ **巨大な数字・ワードマーク・名札・すりガラス**を写す（1〜4）→ 文言を入れる（5）
6. **撮る**（`recipes.md` 10 のスクリプトで PC とスマホ）。拡大して見る。**E のチェックを全部 Yes にするまで直す**。`recipes.md` の「よくある失敗」に当たっていないか見る
7. 最後に飾りを1つ外す
8. **オーナーの判定が出たら、言葉をそのまま A に足す。** 「ダサい」と言われたら、色やフォントの調整で済ませず、構図か体験（型・現象）を変える

## D. 部品

`references/recipes.md` にある。全部、オーナーの判定を通った実装から抜いたもの。**コードを写し、数値を変えない。** 変えるのは色の値と、題材の値の結びつけだけ。

0 骨組み／1 巨大な数字／2 ワードマーク／3 すりガラス／4 端の名札／5 日本語の折り返し／6 ばね／7 粒子の霧／8 色の場／9 部屋ごと変える／10 撮影スクリプト／よくある失敗と直し方

## E. 仕上がりのチェック（全部 Yes になるまで出さない）

- [ ] 最初の5秒に、生きている映像と、触ると返る反応がある
- [ ] 映像は題材の値で変わる（飾りで動いていない）
- [ ] B の3型のどれかで、板で画面を分けていない。パネル・カードを並べていない
- [ ] 物の真似（ダイヤル・計器・地図・紙）になっていない
- [ ] 巨大な数字か語と、小さな名札の差がある。小さいタイトル＋説明文が無い
- [ ] タイトルは英語か単語で句読点なし。名札は端にあって1語
- [ ] 硬い線・四角・切れ目・残像・全面の縦線が無い。ぼかしの端は消えている。ぼかしの下に粒や線を置いていない
- [ ] 映像が画面の端で切れていない（色は端まで、データは内側）
- [ ] 何が何か、どこを触るかが画面の中で分かる
- [ ] 理由なく紙・明朝・レトロに寄っていない
- [ ] 標準の部品を枠に並べていない。キーボードで操作でき、フォーカスが見える
- [ ] スマホで同じ体験。横にはみ出さない。日本語が文の途中で折れていない
- [ ] 下の「AI感の正体」のどれにも当てはまらない
- [ ] 飾りを1つ外した

### AI感の正体（全部避ける）
生成りの背景＋セリフ＋テラコッタ／黒地に蛍光1色／新聞風の細い罫線と段組み／同じ角丸・同じ影のカードの並び／飾りのグラデーション／見出し上の字間を空けた大文字ラベル／「A · B · C」の中黒つなぎ／小さいデータに等幅フォント／ボタンの後ろの「→」／数字タイルの羅列／01・02・03 の番号（順番が無いのに）／見出しの1語だけ色替え／何でも中央揃え／全節に同じふわっと出るアニメーション／見出しの絵文字／Inter・Space Grotesk・Roboto・Noto Sans JP を「とりあえず」／左上の小さいタイトル＋説明文／パネルで区切った定番の画面

## F. 用途ごとの配分（基準は同じ。比重だけ変える）

| 用途 | 映像・驚き | 分かりやすさ | 速さ・軽さ |
| --- | --- | --- | --- |
| 作品（ポートフォリオ） | 最大。「すげぇ」と言う所を1つ | 端の名札で足りる | 重くてもよいが 60fps |
| 自分で毎日使う道具 | 1か所に抑える。毎日見て疲れない | 最大。状態が一目で分かる | 最大。待たせない |
| 他人に売るサービス | 最初の画面だけ強く | 迷わせない。文言は短く具体的 | 速い。スマホ優先 |

## G. レビューのとき

画面に触る変更は、A・B・E で確かめる。当てはまる物を「どこが・なぜ・どう直すか」で具体的に指摘する。好みの問題で済ませない。色やフォントの差し替えで済む指摘と、構図や体験を変えるべき指摘を分けて書く。
